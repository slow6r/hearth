# Мобильный форк: где он и как его собрать

Приложение собирается из форка `simplex-chat`, которого в этом репозитории нет как
каталога — и это не упущение, а следствие двух решений.

Во-первых, форк это отдельный git-репозиторий, клон upstream. Держать его вложенным
каталогом внутри нашего значило бы либо тащить чужую историю в нашу, либо ловить
конфликты при каждом ребейзе на новый тег. Поэтому `/android/simplex-chat/` исключён
в `.gitignore`.

Во-вторых, наши правки живут не в форке, а здесь — в `android/overlay`. Перед сборкой
их раскладывает в дерево форка `android/scripts/sync-overlay.sh`. Так ребейз на новый
upstream-тег остаётся механическим: файлы overlay переносятся поверх, а не мержатся.

## Как восстановить дерево сборки

Наши коммиты поверх тега лежат в `android/fork-patches/` двумя видами — серией
патчей и бандлом того же диапазона. Патчи читаемы глазами и версионируются вместе с
остальным кодом; бандл удобнее, когда нужна история с авторством и датами.

```bash
git clone https://github.com/simplex-chat/simplex-chat.git
cd simplex-chat && git checkout v7.0.1

# либо патчами
git am ../hearth/android/fork-patches/*.patch

# либо бандлом
git fetch ../hearth/android/fork-patches/hearth-mobile-fork.bundle HEAD
git checkout FETCH_HEAD
```

Бандл содержит только наши коммиты и требует, чтобы тег `v7.0.1` уже был в
репозитории: полная история upstream в него намеренно не включена — это сотни
мегабайт чужих объектов, которые проверяющему не нужны.

## Чего в форке нет

Нативного ядра на Haskell. `libsimplex.so` и `libsupport.so` берутся из официального
APK пинованного тега и кладутся туда же, куда их кладёт upstream'овский
`scripts/android/prepare.sh` — см. `android/README.md`, раздел «Стратегия». Мы их не
собираем, и это named-риск: криптографическая часть у нас ровно та же, что у обычных
пользователей SimpleX, не проверенная нами отдельно.

## Сборка и проверка

```bash
android/scripts/bake-node.sh relay.myhearth.ru 7444   # вшить адрес узла (не секрет)
android/scripts/build-release.sh                      # собрать
android/scripts/verify-apk.sh <apk>                   # проверить перед раздачей
```

`verify-apk.sh` ловит ровно те регрессы, которые проще всего внести случайно: Google
и Firebase в зависимостях, `allowBackup`, метку `testOnly`, лишние ABI, адреса
публичной сети SimpleX, отсутствие вшитого адреса узла и — отдельно — появление в
сборке секрета, которого там быть не должно (ADR 0012).
