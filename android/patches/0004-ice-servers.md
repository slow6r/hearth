# 0004 — ICE-серверы: только свой coturn

## Что делаем
Публичные STUN-серверы из дефолтов звонков удаляем. ICE-конфиг берётся из bundle.

## Почему
ТЗ §6.4 и §8.2 п.3. Клиент, ушедший на `stun.l.google.com`, раскрывает свой реальный
адрес третьей стороне — ровно та утечка метаданных, ради устранения которой строится
весь контур.

**Fallback'а быть не должно.** Если ICE пуст — звонок должен честно не состояться.
Молчаливый откат на публичный STUN хуже неработающего звонка.

## Точка интеграции
```bash
rg -n "stun:|turn:|iceServers|RTCIceServer" apps/multiplatform/common/src
```

Значение по умолчанию → `HearthPresets.defaultIceServers(appliedBundle)`.

## Проверка
- A8: при заблокированном P2P среди ICE-кандидатов только `10.66.x.x`.
- `rg "stun\.l\.google\.com" apps/` — пусто.
