# 0011 — Обновление с домашнего узла и самозаведение устройств

## Что делаем
Возвращаем в приложение проверку обновлений — но **только к своему узлу**, не к
третьей стороне. Плюс добавляем экран «Домашний узел» с двумя действиями: «Проверить
обновление» и «Пригласить устройство».

Всё содержательное лежит в overlay (`chat/hearth/HearthUpdate*.kt`,
`HearthSettings*.kt`) и при ребейзе не конфликтует. В чужих файлах — четыре точки.

## Почему
ТЗ §1.4: security-релиз обязан попасть в контур за ≤ 7 дней. Канал из
[0010](0010-no-updates.md) — «приходите домой, обновитесь по LAN» — этого не даёт
именно тому, кто уехал, а он с непропатченной сборкой и остаётся дольше всех.

0010 при этом **не отменяется**: запрет на проверку обновлений у upstream остаётся в
силе. Меняется одно — узел семьи третьей стороной не является, телефон и так держит
с ним постоянное соединение ради доставки сообщений, поэтому запрос обновления не
добавляет наблюдателю ни одного нового факта.

Размен назван прямо, потому что он не мелкий:

* приложению нужно `REQUEST_INSTALL_PACKAGES` — право ставить произвольные APK, тогда
  как [0005](0005-manifest-security.md) разрешения наоборот вычищает;
* на узле появляется публичный HTTP-эндпоинт, которого не было (ADR 0007 сводил
  публичную поверхность к релеям и TURN).

Подробности и альтернативы — `docs/adr/0010-device-api.md`.

Самозаведение устройств секретности не меняет: пароль релея и так лежит на каждом
настроенном телефоне внутри адреса `smp://`, и показать свой QR новому телефону член
семьи может без всякого кода. Меняется **учёт** — узел заводит отдельную запись со
своим токеном, поэтому потерянный телефон отзывается поштучно, а не гашением всех.

## Точки интеграции

### 1. `AndroidManifest.xml` — разрешения и сервис (~16 строк)
```bash
rg -n "uses-permission|FileProvider" apps/multiplatform/android/src/main/AndroidManifest.xml
```
Добавить `REQUEST_INSTALL_PACKAGES` и `FOREGROUND_SERVICE_DATA_SYNC` (с Android 14
foreground-сервису обязателен объявленный тип), а рядом с `FileProvider` —
`<service android:name="chat.hearth.HearthUpdateService" android:exported="false"
android:foregroundServiceType="dataSync" />`.

FileProvider уже объявлен upstream и покрывает `filesDir`, куда пишется загрузка, —
менять его не нужно.

### 2. Экран настроек — пункт «Домашний узел» (~13 строк)
```bash
rg -n "SettingsActionItem" apps/multiplatform/common/src/commonMain/kotlin/chat/simplex/common/views/usersettings/SettingsView.kt
```
Пункт под `appPlatform.isAndroid`: на desktop actual-реализация пустая.

### 3. Настройки приложения — пять префов (~10 строк)
```bash
rg -n "hearthDeviceId|val hearth" apps/multiplatform/common/src/commonMain/kotlin/chat/simplex/common/model/SimpleXAPI.kt
```
`hearthDeviceId`, `hearthEnrolledAt`, `hearthUpdateHost`, `hearthUpdatePort`,
`hearthUpdateToken` — их заполняет импорт bundle, из них собирается транспорт.

### 4. Обновление ICE при запуске (~5 строк)
```bash
rg -n "androidChatInitializedAndStarted" apps/multiplatform/common/src/commonMain/kotlin/chat/simplex/common/platform/Core.kt
```
Сразу после старта чата — `chat.hearth.hearthRefreshIceServers()`.

Это не украшение. Креды TURN — подпись с датой, они протухают по календарю
(`turn.credential_ttl_secs`). Без обновления через месяц звонки перестают проходить
**там, где нужен ретранслятор**, а сообщения продолжают ходить: отказ выглядит как
«иногда работает», и причину ищут где угодно, кроме даты.

Вызов идёт из точки старта, а не из экрана настроек: тот экран человек может не
открыть ни разу за год.

### 5. `gradle.properties` — своя нумерация (~4 строки)
`android.version_name=<тег>-hN`, `android.version_code` строго растёт: именно по коду
приложение решает, новее ли сборка на узле, и Android запрещает откат кода назад.

## Чего Android не позволит
Установить APK без касания человека нельзя никому, кроме device-owner и системных
приложений. Поэтому «в фоне» — про **загрузку**: она живёт в foreground-сервисе,
переживает сворачивание и докачивается по `Range`. Установка всегда показывается
системным диалогом.

## Проверка
- `scripts/verify-apk.sh` (A5): в dex по-прежнему нет обращений к GitHub API и
  `apps.simplex.chat` — обновление ходит только на хост из bundle.
- `aapt2 dump permissions`: ровно два новых разрешения, оба перечислены выше.
- Хеш: `sha256` из манифеста узла обязан совпасть с файлом; несовпадение — загрузка
  удаляется, а не ставится.
- Эндпоинт без токена отвечает 401, лишний файл рядом с APK не отдаётся (404).
