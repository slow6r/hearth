# keys/

Здесь лежат **только публичные** ключи. `.gitignore` устроен как allow-list: по
умолчанию не коммитится ничего, кроме явно перечисленных публичных файлов.

| Файл | Что это | Где приватная часть |
|---|---|---|
| `age-recipients.txt` | Публичные age-ключи получателей бэкапа | YubiKey / офлайн-копия у владельца + вторая у другого взрослого (ТЗ §14) |
| `apksigner-fingerprints.txt` | Отпечатки ключа подписи APK | Hardware-backed токен, в CI отсутствует (ТЗ §8.4) |

## Ключ бэкапа

Генерируется **не на узле** — иначе компрометация узла означала бы компрометацию всех
бэкапов:

```bash
# на доверенной машине
age-keygen -o age-key.txt
# приватную часть — на YubiKey/офлайн-носитель, вторую копию — другому взрослому
# публичную (строка "Public key: age1...") — в hearthd.toml -> backup.recipients
#                                            и сюда, в age-recipients.txt
```

Смысл асимметрии: `hearthd` умеет **создать** архив, но не умеет его **прочитать**.

## Отпечаток ключа подписи APK

```bash
apksigner verify --print-certs hearth-release.apk
```

Записать сюда SHA-256. При установке APK не из внутреннего F-Droid (fallback-канал,
ТЗ §8.2 п.9) отпечаток сверяется вручную — это единственное, что отличает вашу сборку
от чужой.

## Что делать при утере age-ключа

Все существующие бэкапы становятся нечитаемыми — расшифровать их нечем. Порядок:

1. сгенерировать новую пару;
2. обновить `backup.recipients` в `/etc/hearth/hearthd.toml`;
3. `hearthctl backup now` — новый архив уже на новом ключе;
4. старые архивы удалить (они бесполезны);
5. записать инцидент в журнал и **сразу** сделать вторую копию нового ключа.
