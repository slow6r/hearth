# 0104 — Экран кода доступа перед онбордингом

## Что делаем
Пока устройство не заведено и нет полученного bundle, стадия `step1_SimpleXInfo`
показывает `HearthAccessCodeView` вместо экрана «О SimpleX». Код уходит на узел
(`POST /claim`, TLS с пиннингом вшитого CA), полученный bundle кладётся в
`hearthPendingBundle`, стадия переходит сразу на создание профиля.

## Почему
[ADR 0012](../../docs/adr/0012-access-codes.md). Отличия от Android, и почему они есть:
- в запросе `install_id` и `platform: "ios"`: повтор после потерянного ответа не тратит
  код, а в реестре iPhone не записывается Android'ом (оба поля узел понимает);
- имя устройства — модель («Apple iPhone15,2»): имя телефона iOS отдаёт только с
  отдельным правом Apple.

## Точка интеграции
```bash
rg -n "case .step1_SimpleXInfo" apps/ios/Shared/Views/Onboarding/OnboardingView.swift
```
Одно условие в `OnboardingView`, без новой стадии в `OnboardingStage`: новая стадия
сохранялась бы в UserDefaults и переживала бы откат на upstream, а условие — нет.

Цена: экран миграции с другого устройства (из `SimpleXInfo`) до ввода кода недоступен.

## Проверка
- `swift test` в `ios/overlay`: нормализация кода, отказ отправлять неполный код, разбор
  ответов 401/429/409/400.
- Ручная: чистая установка → код → создание профиля без экранов операторов.
