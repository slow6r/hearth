# Runbook: обновление компонентов

ТЗ §10.6. Критерий (§1.4 п.4): **security-релиз upstream попадает в контур ≤ 7 дней**.

## Порядок обязателен

**Сначала клиенты, потом релей.** Upstream периодически режет совместимость со старыми
версиями. Новый клиент со старым релеем обычно работает; старый клиент с новым релеем —
не всегда. Ошибиться порядком = вся семья без связи, пока не откатишь.

## 1. Прочитать changelog

Особое внимание: совместимость релеев и клиентов, изменения формата store log, изменения
в структуре пресетов (ломают ребейз Android-форка).

## 2. Клиенты

```bash
cd android
./scripts/rebase-upstream.sh v6.x.y     # проверит подпись тега, дифф и отсутствие .hs
./scripts/build-release.sh
./scripts/verify-apk.sh <apk>           # A5, A9, отсутствие публичных адресов
# подпись офлайновым ключом (ТЗ §8.4) — ручной шаг
```

Если в диффе появился Haskell — стоп. Это блокер ревью (ТЗ §2.2, §8.3).

## 3. Тестовое устройство — сутки

Одно устройство на новой версии, остальные на старой. Проверить: сообщения, файлы,
звонок, доставку при выключенном экране.

Сутки — не формальность: часть проблем (батарея, переподключение после сна, доставка при
смене сети) видна только на длинной дистанции.

## 4. Остальные клиенты

Через внутренний F-Droid.

## 5. Релей

```bash
# на машине с интернетом: скачать, проверить GPG-подпись, посчитать sha256
# перенести USB на узел
systemctl stop smp-server
install -m 0755 smp-server /usr/local/bin/smp-server
hearthctl manifest pin --name smp-server --version v6.x.y
systemctl start smp-server
hearthctl health
```

Хеши в манифесте обновляются **тем же коммитом**, что и бинарь (ТЗ §10.6 п.4). Иначе
integrity-модуль остановит релей через час — и будет прав.

## 6. Обновления Debian на узле

У узла нет egress, поэтому `apt update` не работает — и это правильно.

Варианты (ТЗ §11):
- **`apt-offline`** — список нужного формируется на узле, скачивается на другой машине,
  переносится USB;
- **временный allow-list в nft** на зеркало Debian, снимаемый сразу после.

Второй вариант проще, но требует дисциплины: правило снимается **в ту же сессию**, и
после этого обязательно проверяется `hearthctl egress` — счётчик за время окна вырастет,
это ожидаемо, зафиксировать в журнале, чтобы потом не расследовать собственную работу.

`unattended-upgrades` остаётся выключенным: перезагрузка в неподходящий момент — это
отсутствие связи у семьи.

## 7. hearthd

```bash
cargo test && cargo clippy --all-targets -- -D warnings && cargo deny check
cargo build --release --target x86_64-unknown-linux-musl
# перенести, затем:
systemctl stop hearthd
install -m 0755 hearthd hearthctl /usr/local/bin/
hearthctl manifest pin --name hearthd --version <новая версия>
systemctl start hearthd
hearthctl status
```

## Журнал

Каждое обновление — строкой: дата, компонент, старая → новая версия, что проверяли.
Через полгода это единственный способ понять, когда что-то начало вести себя иначе.
