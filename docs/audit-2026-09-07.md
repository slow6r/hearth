# Аудит проекта: что нужно исправить

Дата: 2026-09-07. Объём: весь `hearthd` (Rust), деплой-конфигурации, скрипты
инициализации релеев, acceptance-тесты, Android-оверлей, документация.

Сводка: уязвимостей в самом Rust-коде не найдено — кодовая база зрелая
(mTLS с тремя рубежами, fail-closed, запрет `unsafe`/`unwrap`). Основные проблемы
лежат **на стыке кода и развёртывания**: модель прав доступа в `install.sh` и
systemd не согласована с тем, что демону реально нужно, и несколько несущих
функций на живом узле не заработают. Тесты этого не ловят: e2e идёт через
`Sys::new(true)` (dry-run), а acceptance-тесты проверяют режим файла, но не
владельца.

## 🔴 Высокая серьёзность

### 1. Права доступа: hearthd не может ни читать свои секреты, ни писать их

`hearthd.service` запускает демона от `hearth`, но:

- **`/etc/hearth/secrets` — `0700 root:hearth`** (`install.sh:43`). При 0700 группа
  hearth не имеет *никаких* прав. Пароли, записанные туда init-скриптами от root
  (`relays/smp/init-smp.sh:43-44`), становятся `root:root 0600` → `read_secret`
  получает EACCES → **выпуск bundle и ротация TURN-секрета сломаны**.
- **`server.key`/`server.pem`** после `hearthd ca init` (запускается от root,
  иначе не записать в `/etc/hearth/pki`) — `0600 root:root`
  (`src/pki/mod.rs:155-161`). Демон не может их прочитать → admin API не
  поднимается (и молча — см. п. 3).
- **`/etc/opt/simplex` и `/var/opt/simplex` — `0750 simplex:simplex`**
  (`install.sh:40-41`), hearth не в группе simplex → демон не может прочитать
  fingerprint для bundle и заархивировать каталоги при **ежедневном бэкапе**
  (`src/backup/archive.rs:66-74`) — ночной бэкап падает с алертом каждый день.
- После `smp-server init` от root файлы релея (ini, ключи CA) принадлежат root —
  `smp-server` от user `simplex` может не смочь прочитать собственный CA-ключ.
  Ни `chown`, ни `usermod` нигде в репозитории и runbook-ах нет.

**Исправление** (внести в `install.sh`, чтобы шаги не терялись):

```bash
# hearthd читает состояние релеев (fingerprint, бэкап) — дать группе на чтение
usermod -aG simplex hearth
chgrp -R simplex /etc/opt/simplex /var/opt/simplex   # после init-скриптов
chmod -R g+rX /etc/opt/simplex /var/opt/simplex

# секреты: каталог 0750 root:hearth, файлы 0640 root:hearth
install -d -m 0750 -o root -g hearth /etc/hearth/secrets
# после записи каждого пароля из init-скриптов:
chown root:hearth /etc/hearth/secrets/* && chmod 0640 /etc/hearth/secrets/*

# TLS-материал admin API — читаем демону
chown root:hearth /etc/hearth/pki/server.pem /etc/hearth/pki/server.key
chmod 0640 /etc/hearth/pki/server.key
```

Заодно: `hearthctl rotate turn-secret` пишет `/etc/turnserver.conf` — добавить
путь в `ReadWritePaths=` юнита и отдать файл группе hearth (`0644` достаточно:
секрет внутри — нет, там `static-auth-secret`, значит `0640 root:hearth`).

### 2. polkit: мутирующие `systemctl` от user hearth получают Access denied

Supervisor-перезапуски (`src/supervisor/mod.rs:259`), ротация TURN
(`src/configgen/turn.rs:175`), остановка релеев при миграции
(`src/migrate/mod.rs:61`) и integrity-fail (`src/integrity/mod.rs:135`)
выполняют `systemctl restart/stop` от не-root пользователя. Без polkit-правил
systemd отклоняет управление чужими system-юнитами.

**Исправление:** создать `/etc/polkit-1/localauthority/50-local.d/hearthd.pkla`
(или эквивалентный JS-rule), разрешив `hearth` управлять **только** юнитами
`smp-server`, `xftp-server`, `coturn` — не всеми:

```ini
[hearthd manage relay units]
Identity=unix-user:hearth
Action=org.freedesktop.systemd1.manage-units
ResultAny=no
ResultInactive=no
ResultActive=yes
```

…с ограничением по именам юнитов (в JS-rule это `subject.user == "hearth" &&
action.lookup("unit") ...`). Установка — шагом `install.sh`.

### 3. Отказ admin API проглатывается молча

`src/bin/hearthd.rs:215`:

```rust
let api = tokio::spawn(async move { api::serve(api_state, api_shutdown).await });
```

`Result` из spawn никто не проверяет: при ошибке (недоступен `server.key`,
занят порт) демон продолжает работать без админки, **без единой строки в журнале**.

**Исправление:** залогировать ошибку и завершить демон fail-closed:

```rust
let api = tokio::spawn(async move {
    if let Err(e) = api::serve(api_state, api_shutdown).await {
        tracing::error!(error = %e, "admin api failed to start");
        std::process::exit(1); // узел без админки — не «деградация», а отказ
    }
});
```

(или передавать ошибку в основной select!-цикл через oneshot-канал).

## 🟠 Средняя серьёзность

### 4. Скан сокетов egress-детектора не работает и ложно рапортует «ok»

`ss -Htnpa` от пользователя hearth (юнит даёт только `CAP_NET_ADMIN`) не
показывает имена процессов чужих сокетов — для этого нужен root/`CAP_SYS_PTRACE`.
Сокеты smp-server/xftp-server никогда не пройдут фильтр `owned_by` в
`find_foreign` (`src/egress/mod.rs:329`). Хуже: `scanner_is_blind`
(`src/egress/mod.rs:351`) считает скан «зрячим», если хоть один сокет имеет имя —
а собственные сокеты hearthd имена имеют. Итог: `scanner_ok = true`,
`foreign_sockets` всегда пуст — **второй сигнал детектора утечек мёртв, статус
врёт, что всё чисто**.

**Исправление:** считать скан зрячим только тогда, когда имена видны именно на
relay-сокетах (например: на listening-портах 5223/5443 есть хотя бы один сокет
с именем процесса). Если имена там не видны — `scanner_ok = false` и честный
«DEGRADED», как уже делается для нечитаемых счётчиков. Альтернатива —
`CAP_SYS_PTRACE` юниту, но это шире, чем нужно.

### 5. nftables: IPv6-шум ломает инвариант `egress_drop = 0`

`deploy/nftables/hearth.nft`: «домашние» правила и шумовой pre-drop — только
IPv4 (`ip daddr @lan_nets`, строка 124; `ip daddr { 224.0.0.0/4, ... }`,
строка 148). На dual-stack хосте (типичная домашняя сеть с IPv6) исходящие
NDP/RA/mDNS по IPv6 (`ff02::/…`) не матчатся ни одним правилом и попадают в
`egress_drop` → ложные critical-алерты «релейный стек пытался выйти». Счётчик
вообще не привязан к процессу — текст алерта (`src/egress/mod.rs:136-148`)
неточен. Плюс бэкап-таргет по IPv6 не пройдёт `ip daddr @lan_nets`.

**Исправление** (выбрать одно из двух):

- добавить IPv6-ветки:
  ```nft
  set lan6_nets { type ipv6_addr; flags interval; elements = { fd00::/8 } }
  ...
  ip6 daddr @lan6_nets accept
  ip6 daddr ff00::/8 udp dport { 5353, 1900, 137, 138 } drop
  ```
- либо явно отключить IPv6 на узле (`sysctl net.ipv6.conf.all.disable_ipv6=1`)
  и зафиксировать это в runbook-е.

Заодно уточнить текст алерта: «unmatched outbound traffic was dropped», а не
«from the relay stack».

### 6. TURN-over-TLS недонастроен во всех трёх слоях

- Шаблон coturn рендерит `tls-listening-port={{порт}}` (`src/configgen/turn.rs:144-147`),
  но в нём **нет `cert=`/`pkey=`** — coturn без сертификата TLS-листенер не поднимет.
- Порт 5349 **не открыт** в `hearth.nft` (`relay_ports` = 443/5223/5443, отдельного
  правила нет).
- Output-цепочка разрешает coturn только `udp sport 49160-49200` (строка 131):
  TCP-аллокации TURN (`turns:…?transport=tcp`, которые генерирует `ice_servers`
  при заданном `tls_port`) требуют исходящего TCP от coturn и будут заблокированы —
  звонок из «только 443/tcp» сетей соединится и замолчит.

Комментарий в `hearthd.toml:84` предлагает «просто включить tls_port» —
включение не заработает без ручных правок во всех трёх местах.

**Исправление:** добавить в шаблон плейсхолдеры `{{CERT}}`/`{{PKEY}}` (пустые →
`no-tls`/`no-dtls`, как сейчас), открыть порт в nft, и решить судьбу TCP-релея:
либо `meta skuid "turnserver" tcp sport $TURN_MIN-$TURN_MAX` в output, либо
`no-tcp-relay` в шаблоне + убрать `?transport=tcp` из ICE. Пока TLS не собран —
оставить всё как есть, но поправить комментарий в конфиге, чтобы он не обещал
работу в один шаг.

## 🟡 Низкая серьёзность

### 7. Окно прав на секрет при записи

`write_atomic` (`src/store.rs:79-85`) создаёт временный файл через
`File::create` с дефолтной маской (обычно 0644) и делает `chmod 0600` только
после записи, до rename. Краткий период секрет доступен шире; имя временного
файла предсказуемо (`.tmp.<pid>`).

**Исправление:** на unix создавать файл сразу с нужным режимом:

```rust
#[cfg(unix)]
let mut file = {
    use std::os::unix::fs::OpenOptionsExt;
    std::fs::OpenOptions::new().write(true).create_new(true).mode(mode).open(&tmp)?
};
```

### 8. `hearthctl` не URL-энкодит query-параметры

`src/bin/hearthctl.rs:378-384`: `--since 2026-01-01T00:00:00+03:00` — `+`
декодируется сервером в пробел, RFC3339-парсер отказывает.

**Исправление:** процентировать `severity`/`since` (`+` → `%2B`, пробел →
`%20` и т.д.) перед склейкой, либо собирать query через `form_urlencoded`.

### 9. Остатки WireGuard-эры, противоречащие ADR 0007

Релей теперь публичный, но тексты остались:

- `android/overlay/.../HearthOnboarding.kt:75-79` — «Код действует только внутри
  домашней сети или VPN…», «Устройство должно быть подключено к семейному VPN»;
- `src/bin/hearthctl.rs:478` — «Remove the WireGuard peer on the UDM Pro» после
  `device revoke`;
- `tests/acceptance/a03-queue-password.sh:23` — «кто угодно из WG».

**Исправление:** переписать под текущую модель (публичный релей, QR содержит
пароли — беречь, потому что пароли, а не потому что VPN).

### 10. TTL TURN-кредов равен периоду ротации секрета

`hearthd.toml:95-96`: `credential_ttl_secs = 2592000` (30 дней) при
`rotate_days = 30`. Bundle, выпущенный накануне ротации, умрёт через день после
неё: часть устройств **всегда** теряет звонки между ротациями.

**Исправление:** ротировать по календарю с предупреждением за N дней
(«rotate now, bundles issued >20 дней назад — перевыпустить»), либо перевести
перевыпуск bundle в регулярную процедуру и сократить TTL. Как минимум —
`hearthctl rotate turn-secret` должен печатать список устройств с устаревающими
кредами.

### 11. Пароль релея в argv при init

`relays/smp/init-smp.sh:40` — `smp-server init ... --password "$PASSWORD"`:
короткоживущий след в `/proc/<pid>/cmdline`. Разовая операция, но пароль —
«единственный замок» публичного релея.

**Исправление:** если пинованная версия `smp-server init` умеет читать пароль
из ENV/stdin — использовать это; иначе зафиксировать риск в комментарии.

### 12. Admin API: нет таймаутов на handshake и соединения

`src/api/mod.rs:104-127`: зависший TLS-хендшейк или медленный читатель держат
соединение бесконечно. При LAN+mTLS риск низкий.

**Исправление:** обернуть `acceptor.accept` и `serve_connection` в
`tokio::time::timeout` (10–30 с) и закрывать соединение по истечении.

### 13. A4 не проверяет 3478/tcp

`tests/acceptance/a04-port-scan.sh:26-35`: в списке обязательных открытых TCP-портов
только 5223/443/5443, хотя nft и ini публикуют и 3478/tcp.

**Исправление:** добавить 3478 в цикл проверки (TCP-часть), UDP остаётся на A8.

### 14. Лимит устройств: 50 против «≤20» ТЗ

`deploy/hearthd.toml:170` — `max_devices = 50` (комментарий объясняет: 20 человек
× 2–3 устройства), но докстринг `Devices` (`src/config.rs:319-322`) и дефолт
в коде говорят «at most 20 devices».

**Исправление:** согласовать формулировки (ТЗ §1.1 vs ADR) в одном месте и
сослаться на него из докстринга и конфига.

### 15. Baseline egress молча обнуляется при повреждении

`src/egress/mod.rs:56-59`: `store::read_json(...).ok().flatten().unwrap_or_default()`
— битый `egress-counters.json` тихо сбрасывает baseline → повторный critical-алерт
на старые дропы после рестарта.

**Исправление:** различать «файла нет» (норма, первый старт) и «файл есть, но не
парсится» (warning-алерт + старт с нуля явно).

### 16. `/var/opt/simplex-xftp` вне `backup.paths`

Файлы XFTP «в полёте» (TTL 7 дней) не мигрируют и не бэкапятся. Похоже
осознанно (объём), но при `migrate export` недоставленные файлы пропадут
незаметно.

**Исправление:** зафиксировать решение в `docs/runbook-migration.md` («файлы
младше TTL не переносятся — дождитесь доставки или примите потерю»), либо
добавить каталог в `backup.paths` на время миграции.

## Что уже сделано правильно (не трогать)

- Три рубежа админки: подсеть + mTLS + allowlist отпечатков, перечитываемый на
  каждом соединении (мгновенный отзыв, покрыт e2e-тестом).
- `Config::validate` + `deny_unknown_fields`: опечатка в ключе безопасности
  валит демон на старте; wildcard-бинд API и внешние backup/gotify-таргеты
  отвергаются.
- Egress-политика в коде дублирует nftables; fail-closed во всём, включая битый
  `admins.json`.
- coturn: `denied-peer-ip` на все приватные диапазоны, квоты, `no-cli`,
  `no-multicast-peers`.
- Бэкап: age-ключ физически не на узле, tar→gzip→age одним стримом без
  plaintext на диске, `reject_traversal` при распаковке.
- cargo-deny запрещает HTTP-клиентские крейты — исходящие соединения
  архитектурно невозможны.
- Валидация bundle зеркально продублирована на клиенте, включая тонкости
  парсера ICE из `WebRTC.kt`.

## Порядок работы

1. **Сначала п. 1–3** — без них узел не разворачивается по собственному
   runbook-у (`runbook-deploy.md` упрётся в отказ bundle/rotации/бэкапа и
   молча отсутствующую админку).
2. **П. 4–5** — восстанавливают честность двух главных инвариантов проекта
   («детектор утечек работает», «egress_drop = 0»).
3. **П. 6** — до первого включения `tls_port`.
4. Остальное — по ходу, можно в один PR на полировку.
