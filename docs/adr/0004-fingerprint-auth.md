# ADR 0004 — Авторизация админа по отпечатку сертификата

**Статус:** принято · **Дата:** 2026-09-06 · **Уточнение к:** ТЗ §7.3

## Контекст

ТЗ требует mTLS с клиентскими сертификатами от собственного CA `hearthd`. Открытый
вопрос: что считать идентичностью админа после того, как rustls проверил цепочку.

Очевидный вариант — Common Name из сертификата. Он требует X.509-парсера
(`x509-parser` — ещё одна зависимость) и не даёт отзыва: CN нельзя «выключить».

## Решение

Идентичность админа — **sha256 DER-сертификата**. `hearthd ca issue <name>` записывает
отпечаток в `/etc/hearth/pki/admins.json`; API на каждом соединении перечитывает этот
файл и требует, чтобы отпечаток присутствовал, не был отозван и не просрочен.

Опционально в конфиге можно дополнительно закрепить список разрешённых отпечатков
(`api.allowed_admin_fingerprints`) — второй, независимый от файла реестра замок.

## Обоснование

1. **Отзыв работает мгновенно.** Реестр перечитывается на каждом соединении, поэтому
   `hearthd ca revoke owner` действует без перезапуска демона. Покрыто e2e-тестом.
2. **Нет X.509-парсера.** Разбор сертификатов в привилегированном демоне — исторически
   богатый источник уязвимостей. Здесь его просто нет: rustls проверил цепочку, мы
   считаем sha256 байтов.
3. **Отпечаток невозможно подделать переименованием.** Два сертификата с CN `owner` —
   это два разных отпечатка, и второй не пройдёт.

## Последствия

- Перевыпуск сертификата админа требует обновления реестра — это делает та же команда
  `ca issue`, так что дополнительного шага нет.
- В логах видно имя админа (из реестра) и отпечаток, но не содержимое сертификата.
- CRL/OCSP не нужны: реестр и есть список отзыва, локальный и мгновенный.
