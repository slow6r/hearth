# ADR 0016 — Свой push-сервер: APNs и правка Haskell

**Статус:** принято · **Дата:** 2026-09-14 · **Отступает от:** ТЗ §1.1 и §3.1 (без
push-инфраструктуры Apple), ТЗ §2.2 и §8.3 (любой diff в Haskell — блокер), README
(узел ничего не инициирует сам) · **Уточняет:** [ADR 0015](0015-ios-client-app-store.md)

## Решение

На узле работает `ntf-server` из simplexmq — тот же тег, что у релеев, плюс одна правка.
Он отправляет уведомления iPhone через Apple Push Notification service. Приложение
Hearth ходит за уведомлениями только к нему.

Для этого сделано три отступления, и все три названы здесь, а не спрятаны в коде:

1. **Правка ядра клиента** ([ios/patches/0101](../../ios/patches/0101-ntf-servers-from-env.md)):
   адрес push-сервера берётся из переменной окружения, которую выставляет приложение;
   без неё — push-серверов нет вовсе.
2. **Правка `ntf-server`** ([relays/ntf/patches/0001](../../relays/ntf/patches/0001-apns-team-and-topic-from-env.patch)):
   команда и topic Apple — из окружения. Сток прошит на приложение SimpleX
   (`appTeamId = "5NN7GUYB6T"`, `appName = "chat.simplex.app"`) и нашему слать не может.
3. **Исходящая дыра в nftables:** пользователь `simplex-ntf`, только TCP 443, только
   `17.0.0.0/8` (сеть Apple), отдельный счётчик `ntf_egress`.

Как это устроено на узле — [docs/runbook-ntf.md](../runbook-ntf.md): порт `2053/tcp`
(443 и 5223 режет провайдер узла, 8443 занят SMP), секция `[ntf]` в `hearthd.toml`,
выключенная по умолчанию, ключ APNs через `LoadCredential` из `/etc/credstore`.

## Почему

iOS не даёт приложению держать соединение в фоне. Без push приложение получает
сообщения, только пока открыто: о сообщении человек узнаёт, открыв приложение сам.
Для мессенджера семьи это не «хуже», это «не работает».

| Вариант | Почему нет |
|---|---|
| Без push | сообщения не приходят, пока приложение закрыто |
| Push-сервер SimpleX | третья сторона видит токен устройства и расписание уведомлений; нужен стоковый bundle ID, то есть не наше приложение |
| Фоновое обновление iOS | запускается по усмотрению системы — часы, а не секунды; upstream называет его «Periodic» и всё равно ходит через push-сервер |
| **Свой `ntf-server`** | уведомления мгновенные; третья сторона — только Apple, и без неё на iOS не бывает |

## Чего это стоит

**Apple видит время.** Шифрованное уведомление уходит на токен устройства в момент, когда
для него пришло сообщение. Содержимого, отправителя и размера Apple не видит — полезная
нагрузка шифруется для расширения на телефоне. Но «на этот iPhone пришло что-то в 23:14»
Apple знает, и знает, что прислал его наш узел. Для Android такого наблюдателя нет.

**Узел начинает инициировать соединения.** Инвариант «`egress_drop` за сутки — ноль»
остаётся, но утверждение «узел ничего не инициирует сам» больше не верно без оговорки: к
TURN-медиа добавился `ntf-server` → Apple. Дыра узкая (один пользователь, один порт, одна
сеть) и считается отдельно, чтобы `egress_drop` оставался читаемым. Сторож egress знает
про это исключение по процессу и адресу назначения, а не через `lan_networks`: тот
список — ещё и политика самого `hearthd`.

**Дыра шире, чем APNs.** `17.0.0.0/8` — вся сеть Apple, а не только push-шлюзы: процесс
`simplex-ntf` достанет до любого сервиса Apple на 443. Сузить до адресов APNs нельзя —
Apple их не фиксирует. Сторож egress сверяет процесс, сеть и порт одновременно
(`egress.process_allow`), так что тот же адрес от релея остаётся инцидентом.

**Ключ APNs живёт на узле, доступном из интернета.** Командный ключ Apple годится для
любого приложения команды — не только для Hearth. Захват узла дал бы возможность слать
уведомления пользователям всех приложений этой команды. Если Apple позволяет выпустить
ключ, ограниченный одним topic и окружением, — брать его. Если нет — это принятый риск,
и ключ отзывается одной кнопкой в аккаунте ([docs/runbook-ntf.md](../runbook-ntf.md)).
Со своей стороны: файл `0600 root:root`, в службу попадает через `LoadCredential`,
`hearthd` его не читает, в ночной бэкап он не входит.

**На узле появляется PostgreSQL.** В simplexmq v7.0.1 `ntf-server` без него не
собирается: токены и подписки живут только в базе. Это новое состояние узла — дамп перед
ночным бэкапом (`ntf-db-dump.timer`), а при переезде базу переносят отдельно от архива
`migrate export`. Потеря базы не трогает переписку, но телефоны перестают получать
уведомления до перерегистрации токена; перерегистрирует ли клиент сам — не проверено.

**Порядок обновления узла стал важен.** Правило nftables ссылается на пользователя
`simplex-ntf`, а nft разрешает имена при загрузке: новый `hearth.nft` или
`hearthd.service` без `install.sh`, который этого пользователя заводит, не загрузятся — и
узел не поднимется. `install.sh` заводит пользователя на любом узле, даже где ntf выключен.

**Haskell больше не «ноль строк».** Правило ТЗ §2.2 существовало, чтобы ребейз оставался
механическим и чтобы крипта upstream оставалась чужой проверенной. Обе правки не трогают
ни протокол, ни крипту: одна меняет список адресов по умолчанию, другая — две константы.
Ребейз теперь проверяет Haskell по списку разрешённых файлов
([ios/patches/haskell-allowlist.txt](../../ios/patches/haskell-allowlist.txt)) и печатает
их дифф, а любой другой `.hs` по-прежнему останавливает его.

**`ntf-server` собирается из исходников.** Правку нельзя положить в готовый бинарь.
Сборка — `relays/ntf/build-ntf-server.sh` от закреплённых входов (образ по digest, GHC
9.6.3, коммит тега); хеш бинаря пинуется в манифесте, как у остальных. Включённый релей
без записи в манифесте `hearthd` считает нарушением целостности и уводит узел в карантин.
Патч переносится на каждый новый тег simplexmq.

**Две поправки к окружению, без которых сервер не поднимется на Debian:** он прошит на
`/etc/ssl/cert.pem` и на системный резолвер, а у узла резолвера нет. Юнит подменяет
ему оба файла через bind mount, не трогая остальную систему.

## Что осталось незакрытым

- **Молчание Apple неотличимо от молчания узла.** Если уведомления перестали приходить,
  с телефона не видно, где обрыв. Проверка — журнал `ntf-server` и рост `ntf_egress`.
- **Правка `ntf-server` просится в upstream.** Переменные окружения с запасными
  значениями upstream никому не мешают; принятый PR убрал бы и сборку из исходников, и
  этот пункт ADR.
- **Android не меняется.** Там доставка по-прежнему без push, и расписание сообщений
  Google не видит.
