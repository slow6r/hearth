# ADR 0008 — Многоцелевой узел: egress по пользователям

**Статус:** принято · **Дата:** 2026-09-07 · **Уточняет:** [ADR 0007](0007-public-relay-no-vpn.md), ТЗ §5.4, §7.4

## Контекст

Узел разворачивается не на выделенной «тупой трубе», а на машине, которая стоит в
спортзале, подключена к телевизору и используется для занятий по Zoom и VK Звонкам.
Плюс владелец планирует ставить туда свои приложения и мониторинг.

Прежняя модель — `output` policy drop, разрешён только LAN и медиа coturn —
несовместима с этим буквально: браузер не выйдет в интернет.

Самый простой выход, «открыть исходящий трафик целиком», уничтожил бы единственное
свойство, ради которого писался модуль `egress`.

## Решение

Egress разрешается **поимённо, по владельцу сокета**, с раздельными счётчиками:

```nft
meta skuid "turnserver" udp sport $TURN_MIN-$TURN_MAX counter name turn_egress accept
meta skuid { "gym", "root" }                          counter name app_egress  accept
counter name egress_drop log prefix "hearth-egress-drop " drop
```

Релейный стек (`simplex`, `hearth`) в списке отсутствует и остаётся под запретом.

## Что изменилось по смыслу

| | Было | Стало |
|---|---|---|
| `egress_drop = 0` означает | «эта машина ничего не инициирует наружу» | «**релейный стек** не пытался выйти в интернет» |
| Что считается инцидентом | любой исходящий пакет | исходящий пакет от `smp-server` / `xftp-server` |
| Разрешённый egress | только медиа coturn | + `gym`, `root`, при необходимости другие |

Претензия сузилась. Но она осталась той, которая имеет значение: `simplex` и `hearth` —
единственный код на этой машине, который никто построчно не читает. Браузер владелец
ставит осознанно, стоковый Haskell-бинарь релея — нет.

## Побочная находка: сканер сокетов был сломан

Проверяя это изменение, обнаружили, что после [ADR 0007](0007-public-relay-no-vpn.md)
модуль `egress` считал находкой **любой** установленный сокет релея к не-домашнему
адресу. Но с публичным релеем это ровно то, что происходит постоянно: члены семьи
подключаются из интернета. Сканер поднимал бы критический алерт на каждое нормальное
подключение.

Исправлено: находкой считается сокет, у которого **локальный порт не входит в наши
опубликованные** (5223/443/5443). Принятое соединение сохраняет порт прослушивания
локально; исходящее получает эфемерный порт. Разница ровно в направлении, и именно
она отличает утечку от клиента.

Плюс: `ss` показывает имена процессов только для сокетов, которые вызывающему
позволено просматривать. Если ни один сокет не назвал процесс, сканер ничего не
доказывает — теперь он сообщает `scanner_ok: false`, а не «чисто». Это тот же принцип,
что и с нечитаемыми счётчиками nft: слепой наблюдатель выглядит как чистый узел.

## Последствия

- Добавление сервиса, которому нужен интернет, — это правка `hearth.nft`: имя
  пользователя в правило `app_egress`. Финальный `drop` не трогается никогда.
- `root` в списке. Это не ослабляет модель заметно: рутом можно просто выгрузить
  правила. Зато без него нет `apt update`.
- **Резолвер на узле включён** — вопреки ТЗ §5.2. Браузеру и Zoom нужен DNS. Свойство
  «имён нет, нечего перехватывать» сохраняется только для клиентских адресов: они
  по-прежнему могут быть IP-литералами, а `node.host` резолвится на стороне клиента.
- Приложения зала ставятся через **Flatpak** ради песочницы: она ограничивает доступ
  к файловой системе, где рядом лежит приватный ключ CA релея.
- Разделение пользователей (`gym` без sudo) защищает ключи от человека, подошедшего к
  включённой машине, — то есть работает круглосуточно, в отличие от LUKS.

## Альтернатива, которая была отвергнута

Вторая машина: узел однозадачный, десктоп отдельно. Технически чище — `egress_drop`
остался бы абсолютным нулём.

Отвергнуто владельцем по практическим причинам: машина уже стоит в зале у телевизора и
используется для занятий, вторая коробка там не нужна. Решение зафиксировано как
осознанный компромисс, а не как недосмотр.
