# ADR 0008 — Многоцелевой узел: egress по пользователям

**Статус:** принято · **Дата:** 2026-09-07 · **Уточняет:** [ADR 0007](0007-public-relay-no-vpn.md), ТЗ §5.4, §7.4

## Контекст

Узел разворачивается не на выделенной «тупой трубе», а на машине, которая стоит в
спортзале, подключена к телевизору и используется для занятий по Zoom и VK Звонкам.
Плюс владелец планирует ставить туда свои приложения и мониторинг.

Прежняя модель — `output` policy drop, разрешён только LAN и медиа coturn —
несовместима с этим буквально: браузер не выйдет в интернет.

Самый простой выход, «открыть исходящий трафик целиком», уничтожил бы единственное
свойство, ради которого писался модуль `egress`.

## Решение

Egress разрешается **поимённо, по владельцу сокета**, с раздельными счётчиками:

```nft
meta skuid "turnserver" udp sport $TURN_MIN-$TURN_MAX counter name turn_egress accept
meta skuid { "gym", "root" }                          counter name app_egress  accept
counter name egress_drop log prefix "hearth-egress-drop " drop
```

Релейный стек (`simplex`, `hearth`) в списке отсутствует и остаётся под запретом.

## Что изменилось по смыслу

| | Было | Стало |
|---|---|---|
| `egress_drop = 0` означает | «эта машина ничего не инициирует наружу» | «**релейный стек** не пытался выйти в интернет» |
| Что считается инцидентом | любой исходящий пакет | исходящий пакет от `smp-server` / `xftp-server` |
| Разрешённый egress | только медиа coturn | + `gym`, `root`, при необходимости другие |

Претензия сузилась. Но она осталась той, которая имеет значение: `simplex` и `hearth` —
единственный код на этой машине, который никто построчно не читает. Браузер владелец
ставит осознанно, стоковый Haskell-бинарь релея — нет.

## Побочная находка: сканер сокетов был сломан

Проверяя это изменение, обнаружили, что после [ADR 0007](0007-public-relay-no-vpn.md)
модуль `egress` считал находкой **любой** установленный сокет релея к не-домашнему
адресу. Но с публичным релеем это ровно то, что происходит постоянно: члены семьи
подключаются из интернета. Сканер поднимал бы критический алерт на каждое нормальное
подключение.

Исправлено: находкой считается сокет, у которого **локальный порт не входит в наши
опубликованные** (5223/443/5443). Принятое соединение сохраняет порт прослушивания
локально; исходящее получает эфемерный порт. Разница ровно в направлении, и именно
она отличает утечку от клиента.

Плюс: `ss` показывает имена процессов только для сокетов, которые вызывающему
позволено просматривать. Если ни один сокет не назвал процесс, сканер ничего не
доказывает — теперь он сообщает `scanner_ok: false`, а не «чисто». Это тот же принцип,
что и с нечитаемыми счётчиками nft: слепой наблюдатель выглядит как чистый узел.

## Последствия

- Добавление сервиса, которому нужен интернет, — это правка `hearth.nft`: имя
  пользователя в правило `app_egress`. Финальный `drop` не трогается никогда.
- `root` в списке. Это не ослабляет модель заметно: рутом можно просто выгрузить
  правила. Зато без него нет `apt update`.
- **Резолвер на узле включён** — вопреки ТЗ §5.2. Браузеру и Zoom нужен DNS. Свойство
  «имён нет, нечего перехватывать» сохраняется только для клиентских адресов: они
  по-прежнему могут быть IP-литералами, а `node.host` резолвится на стороне клиента.
- Приложения зала ставятся через **Flatpak** ради песочницы: она ограничивает доступ
  к файловой системе, где рядом лежит приватный ключ CA релея.
- Разделение пользователей (`gym` без sudo) защищает ключи от человека, подошедшего к
  включённой машине, — то есть работает круглосуточно, в отличие от LUKS.

## Альтернатива, которая была отвергнута

Вторая машина: узел однозадачный, десктоп отдельно. Технически чище — `egress_drop`
остался бы абсолютным нулём.

Отвергнуто владельцем по практическим причинам: машина уже стоит в зале у телевизора и
используется для занятий, вторая коробка там не нужна. Решение зафиксировано как
осознанный компромисс, а не как недосмотр.

## Дополнение от 2026-09-09: список пользователей по факту развёртывания

При развёртывании на `fels` выяснилось, что пример выше **не загружается**. Три
причины, все обнаружены `nft -c -f`:

1. **Пользователя `gym` на машине нет.** Десктоп-сессия у телевизора, Sunshine и
   браузер работают от `fels` (uid 1000) — того же пользователя, что и админский.
   Разделение «зал без sudo», описанное выше, на этой машине не реализовано:
   `fels` состоит в sudo. Это отдельное отступление, см. ниже.
2. `$TURN_MIN-$TURN_MAX` не парсится: nft читает `$TURN_MIN-` как самостоятельный
   идентификатор. Диапазон должен быть одним `define TURN_RANGE = 49160-49200`.
3. Счётчики `app_egress` и `turn_egress` использовались, но не были объявлены.
   `counter name X` требует объявленного объекта-счётчика.

Фактический список на `fels`:

```nft
meta skuid "turnserver" udp sport $TURN_RANGE counter name turn_egress accept
meta skuid { "root", "_apt", "fels", "youcando", "zerotier-one",
             "systemd-timesync" }             counter name app_egress  accept
counter name egress_drop log prefix "hearth-egress-drop " drop
```

| Имя | Зачем | Что ломается без него |
|---|---|---|
| `root` | cloudflared, docker, apt, certbot | Туннель Cloudflare рвётся → сайт игры недоступен снаружи |
| `_apt` | apt сбрасывает права на этого пользователя при скачивании | `apt update` молча не работает: сам apt от root, а `/usr/lib/apt/methods/http` — от `_apt` |
| `fels` | десктоп у телевизора: браузер, Zoom, VK Звонки, Sunshine | То, ради чего писался ADR 0008 |
| `youcando` | Next.js + сервер лицензий → Яндекс ID, Google, ЮKassa | **Вход и оплата на сайте перестают работать, а сайт продолжает отдавать 200.** Отладка занимает часы |
| `zerotier-one` | оверлей ZeroTier | Теряется второй путь управления узлом |
| `systemd-timesync` | NTP | Роутер (UDM) NTP не отдаёт — проверено. От часов зависят TURN-креды (REST-схема с истечением) и сертификаты admin API |

Намеренно отсутствуют: `www-data` (nginx проксирует только на localhost, наружу не
ходит — проверено по `nginx -T`), `prometheus` (скрейпит только localhost),
и, разумеется, `simplex` и `hearth`.

Плюс отключён `fwupd-refresh.timer`: он ходит в интернет от собственного
пользователя и капал бы в `egress_drop`, превращая «ноль» в «примерно ноль».

### Правило про link-local, которого не хватало

Строка «всё остальное молча дропаем, чтобы `egress_drop` не шумел» в исходной
редакции роняла заодно **ответы NDP и ответы mDNS**. Последствия оказались шире, чем
шум в счётчике:

- без neighbour advertisement IPv6 на линке не работает вовсе — а `ssh fels`
  резолвится через mDNS именно в `fe80::`, и соединение молча висит до таймаута;
- без ответов mDNS имя `fels` перестаёт резолвиться **во всей домашней сети** — по
  нему в эту машину ходят и ssh, и Moonlight.

Обе категории теперь принимаются явно, со своим счётчиком `link_local`; молча
дропается только остальное.

### Разделение пользователей на fels не выполнено

Раздел «Последствия» выше обещает: «Разделение пользователей (`gym` без sudo) защищает
ключи от человека, подошедшего к включённой машине». На `fels` этого нет: тот же
`fels`, от которого идёт десктоп-сессия у телевизора, состоит в sudo с NOPASSWD.

Значит человек за незалоченной машиной в зале получает root, а с ним ключ CA релея.
Вместе с [ADR 0009](0009-no-full-disk-encryption.md) (нет LUKS) это означает, что
физический доступ к машине = полный доступ к контуру. Компенсации нет; это цена
того, что узел и десктоп зала — одна машина.

Обратная ссылка, чтобы расхождение не воспроизвелось: таблица «Чем это компенсируется»
в [ADR 0009](0009-no-full-disk-encryption.md) в редакции от того же 2026-09-09
засчитывала разделение пользователей как **сделанное** и выводила из него, что
подошедший к сессии `fels` ключей не получит. Два ADR, принятых в один день, утверждали
противоположное; правда — в этом разделе. ADR 0009 исправлен 2026-09-18, и строка там
теперь ссылается сюда.

Приведение к описанному в ADR виду — отдельная работа: завести пользователя зала без
sudo, перенести в него автологин и сессию Sunshine, убрать `fels` из sudo и оставить
админский доступ только по ssh-ключу. Ничего в hearth от этого не зависит, кроме имени
в правиле `app_egress`. Порядок шагов, который не запирает дверь и не роняет ruleset:
[runbook-host-hardening.md](../runbook-host-hardening.md) §2.1.

### Автовход и незалоченный экран — это тоже принятый риск, а не пункт плана

Дополнение 2026-09-18, по снятому состоянию узла. Выше автовход упоминался только как
будущая работа; по факту он уже настроен, и настроен на ту же учётку:

```
/etc/gdm3/daemon.conf:  AutomaticLoginEnable=true
                        AutomaticLogin=fels
sudoers:                fels ALL=(ALL:ALL) ALL
                        fels ALL=(ALL) NOPASSWD: ALL   (и дубль в /etc/sudoers.d/99-fels)
сессия:                 gdm3, Wayland, seat0 активна, блокировка экрана выключена
```

Связка «автовход + выключенный локскрин» пришла из
[runbook-install-beelink.md](../runbook-install-beelink.md) §3–§4 вместе с командами, но
без своей посылки: там она обоснована тем, что учётка зала бесправна. Здесь она
бесправной не является. Итог, который до сих пор нигде не был записан как принятый:
**машина 24/7 стоит с открытой root-эквивалентной сессией; DPMS гасит телевизор, но не
блокирует сессию.**

Почему не «просто включить блокировку»: Sunshine стримит именно эту графическую сессию,
а залоченная сессия GNOME под Wayland не отдаёт ни картинку, ни ввод, и разблокировать
её удалённо нечем — занятие с телевизора перестанет запускаться без человека у
клавиатуры. Развилка разобрана в [runbook-host-hardening.md](../runbook-host-hardening.md) §1.3;
дешёвый шаг, который не трогает зал вообще, — убрать `NOPASSWD` (§1.2).

Чего в этом списке нет и не будет: сужения `sudo` «до команд, нужных демону». `hearthd`
не вызывает `sudo` ни разу — он работает от `hearth` с `CAP_NET_ADMIN` (для
`nft -j list counters`) и управляет четырьмя юнитами через правило polkit
`49-hearthd.rules`. `sudo` на этом узле нужен только человеку, а человеку нужны
`install.sh`, `nft -f` и `apt` — каждая из этих команд root-эквивалентна, и список из
них был бы списком-театром.
