# ADR 0010 — Device API: публичный сервис узла для самих телефонов

**Статус:** принято · **Дата:** 2026-09-10 · **Уточняет:** [ADR 0007](0007-public-relay-no-vpn.md) · **Заменяет:** [patches/0010-no-updates.md](../../android/patches/0010-no-updates.md) в части «обновлений нет»

## Решение

На узле появляется третий слушающий сервис, доступный из интернета: `device_api`,
порт 7444. Он умеет ровно две вещи и обе — только для устройств семьи, по токену:

1. отдать манифест обновления и сам APK (с докачкой);
2. выписать свежие TURN-креды.

## Контекст: две проблемы, которые иначе не решаются

### Обновление не доходит до того, кто уехал

`patches/0010-no-updates.md` выключает проверку обновлений и предлагает раздачу через
домашний F-Droid. Причина выключения названа там точно: «проверка обновлений —
исходящее соединение **к третьей стороне**, плюс она раскрывает факт использования
сборки».

Узел семьи третьей стороной не является, и телефон и так держит с ним постоянное
соединение — это режим доставки сообщений. Значит запрос обновления не сообщает
наблюдателю ни одного нового факта.

А вот раздача «приходите домой и обновляйтесь по LAN» не работает для того, кто в
отъезде. И это ровно тот человек, который дольше всех остаётся с непропатченной
сборкой, — при требовании ТЗ §1.4 втащить security-релиз за ≤ 7 дней.

### Звонки ломаются раз в месяц, и симптом читается неверно

TURN-креды в bundle — это HMAC текущего секрета. При ротации они умирают у всех
устройств сразу. Код это прямо описывает (`api/routes.rs`, `rotate_turn_secret`):

> credentials from the old secret are dead; re-issue bundles for the devices listed
> below — **calls break, messages do not**, so the symptom is easy to misread

То есть каждые `rotate_days` кто-то должен вручную раздать новый bundle на все
телефоны, иначе звонки перестают работать, а сообщения продолжают ходить. Симптом
выглядит как «сломался микрофон», а не «протухли креды».

Здесь телефон берёт свежие креды сам, и ротация перестаёт быть событием.

## Чего это стоит

**Публичная поверхность узла растёт, и растёт нашим кодом.** ADR 0007 свёл её к
релеям и TURN — то есть к стоковому upstream, который читают тысячи глаз. Device API
написан здесь и прочитан одним человеком. Это главная цена, и её надо называть первой.

**Приложению нужно `REQUEST_INSTALL_PACKAGES`** — право ставить произвольные APK.
`patches/0005` разрешения наоборот вычищает. Размен, а не мелочь.

**Токен устройства — новый долгоживущий секрет** на каждом телефоне.

## Что сделано, чтобы это было приемлемо

| Мера | Где |
|---|---|
| Отдельный слушатель, не admin API | разные порты, разные модели доверия; ошибка в маршрутизации не даёт прав админа |
| Токен на устройство, а не общий | `device revoke` гасит доступ одного телефона, не трогая остальных |
| Сравнение токена в постоянное время | `ct_eq`, чтобы токен нельзя было подобрать по времени ответа |
| Отозванный и несуществующий токен неотличимы | оба дают 401 без подробностей |
| Имя файла проверяется, а не подставляется | `is_safe_apk_name`; `..%2f..%2fetc%2fshadow` отвергается — тест на это есть |
| Адрес узла клиент берёт из bundle, не из ответа API | подменённый манифест не может увести загрузку на чужой сервер |
| Файл отдаётся потоком с ограничением длины | узел — мини-ПК, APK весит 248 МБ |
| TLS с сертификатом hearth CA на `node.host` | приложение пинует CA; публичный CA не нужен |

### Почему свой CA, а не Let's Encrypt

Публичный сертификат означал бы certbot, который однажды молча не продлится и оставит
семью без обновлений именно тогда, когда обновление нужно. Плюс запись в
Certificate Transparency — постоянную и публично доступную поиском.

Пиннинг своего CA — то же, что мессенджер уже делает с адресом релея: отпечаток CA
зашит в клиентский адрес. Здесь та же модель, просто для второго сервиса.

## Что осталось нерешённым

- **Android не даёт установить APK без нажатия человека.** Скачивание идёт в фоне и
  переживает сворачивание; установку всегда показывает системный диалог. Обойти это
  может только device-owner или системное приложение.
- **Устройства, заведённые до появления токенов**, получают bundle без секции `node` и
  живут как раньше: их звонки сломаются на следующей ротации. Лечится перевыпуском
  bundle.
- **Сам device API не обновляется по воздуху** — он часть `hearthd`, а тот
  обновляется руками по [runbook-updates.md](../runbook-updates.md).

## Альтернатива, которая была отвергнута

**Раздача только из дома (LAN/ZeroTier).** Ноль новой публичной поверхности, и это
серьёзный аргумент. Отвергнуто потому, что не выполняет требование о семи днях для
того, кто уехал, — а именно он и остаётся уязвимым. Проблему с TURN-кредами этот
вариант тоже не решает.
