# ADR 0001 — Что пишем на Rust, а что не трогаем

**Статус:** принято · **Дата:** 2026-09-06 · **Основание:** ТЗ §0

## Контекст

Соблазн «переписать на Rust» в проекте про безопасность возникает сам собой. ТЗ его
явно блокирует: криптопротокол, релеи и логика очередей остаются upstream-Haskell.

## Решение

На Rust пишется **только то, у чего нет предшественника в SimpleX**: supervisor,
egress-watchdog, integrity, backup, config-gen, admin API, migrate.

Граница проведена так: если функциональность существует в upstream в любом виде — она
не переписывается. Если её нет вообще (например, «читать счётчики nftables и поднимать
инцидент») — это наш код.

## Последствия

- `hearthd` не знает форматов SimpleX. Он читает `fingerprint` как непрозрачную строку
  и собирает из неё адрес по шаблону — но не парсит протокол и не валидирует крипту.
- Обновление upstream не требует изменений в `hearthd`, кроме хешей в манифесте.
- Цена: `hearthd` не может диагностировать проблемы **внутри** релея. Он видит порт,
  юнит и хеш бинаря — и этого достаточно для его задач.

## Альтернативы

- **Свой релей на Rust.** Отвергнуто: это переписывание протокола, то есть новая крипта
  без аудита. Прямо запрещено ТЗ §1.2/§2.2.
- **Патчи в Haskell ради телеметрии.** Отвергнуто: любой diff в Haskell — блокер ревью,
  и он ломает дешёвый ребейз на security-релиз (ТЗ §1.4).
