# iOS и Desktop: ручная настройка стокового клиента

ТЗ §9. В v1 своего iOS-клиента нет (§13), поэтому используется стоковое приложение
SimpleX Chat с ручной настройкой.

## Откуда берётся чек-лист

Не отсюда. Печатается на узле — из того же состояния, что и bundle, поэтому адреса и
TURN-креды в нём заведомо актуальны:

```bash
hearthctl device add "Папа — iPhone 15" --platform ios
hearthctl device checklist papa-iphone-15
```

Этот файл описывает **что и зачем**; конкретные строки с паролями — только на экране
администратора, внутри WG.

## Шаги (те же 6, что печатает hearthctl)

### 1. WireGuard
Устройство подключено к семейному WG. Проверка: `10.66.10.10` доступен.
Без VPN мессенджер не работает — по дизайну (ТЗ §14).

### 2. Выключить операторов
`Настройки → Network & servers → Operators`: выключить **всех** (SimpleX Chat, Flux и
любых других).

Это самый важный шаг и самый легко забываемый. Оставленный включённым оператор означает,
что часть трафика пойдёт через публичные релеи — то есть контур не выполняет свою задачу.
На Android этот экран просто скрыт (`patches/0002`), на стоковом iOS его надо выключить
руками.

### 3. SMP-сервер
Удалить все предустановленные, добавить один — `smp://<fp>:<pass>@10.66.10.10:5223`.
Отметить «Use for new connections».

### 4. XFTP-сервер
Аналогично: `xftp://<fp>:<pass>@10.66.10.10:5443`.

### 5. ICE-серверы
`Settings → Audio & video calls → WebRTC ICE servers`: заменить содержимое на
`stun:10.66.10.10:3478` и `turn:10.66.10.10:3478` с выданными username/credential.
Публичные STUN удалить.

TURN-креды короткоживущие (по умолчанию сутки, ТЗ §6.4 + `turn.credential_ttl_secs`). Для
постоянного устройства имеет смысл увеличить TTL в конфиге узла либо перевыпускать
чек-лист — иначе звонки перестанут работать через сутки, а сообщения продолжат.

### 6. Приватность и уведомления
- Private message routing: **Always**;
- Notifications: **Instant** (Push/Periodic не использовать — сервера уведомлений в
  контуре нет);
- Исчезающие сообщения — включить для новых контактов (7 дней), как на Android;
- Экранная блокировка приложения (Face ID / пароль) — включить;
- iCloud Backup для приложения — **выключить** (аналог `allowBackup=false`, ТЗ §3.1).

## Проверка

- В списке серверов ровно один SMP и один XFTP, оба `10.66.10.10`.
- Операторы выключены все.
- Отправка и получение сообщения работают.
- Звонок: кандидаты только `10.66.x.x` (A8).

## Чего стоит ожидать

| | Android (форк) | iOS (сток) |
|---|---|---|
| Настройка | один QR, ≤ 5 минут | 6 шагов вручную |
| Пресеты операторов | экрана нет | можно случайно включить обратно |
| FLAG_SECURE | всегда | нет аналога |
| Бэкапы ОС | запрещены манифестом | выключать вручную в iCloud |
| Обновления | внутренний F-Droid | App Store, стоковая сборка |

Отсюда рекомендация: пока iOS-форка нет (фаза 2, ТЗ §13), стоковые iOS-устройства
считать **менее защищёнными** и держать это в голове при добавлении людей в контур.
