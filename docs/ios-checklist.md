# iOS и Desktop: ручная настройка стокового клиента

ТЗ §9. В v1 своего iOS-клиента нет (§13), поэтому используется стоковое приложение
SimpleX Chat с ручной настройкой.

## Откуда берётся чек-лист

Не отсюда. Печатается на узле — из того же состояния, что и bundle, поэтому адреса и
TURN-креды в нём заведомо актуальны:

```bash
hearthctl device add "Папа — iPhone 15" --platform ios
hearthctl device checklist papa-iphone-15
```

Этот файл описывает **что и зачем**; конкретные строки с паролями — только на экране
администратора и на бумажке, которую потом уничтожают.

## Шаги (те же 6, что печатает hearthctl)

### 1. Сеть
Никакой VPN не нужен: релей доступен из интернета. Проверка: `nc -vz <node.host> 5223`
отвечает с телефона по мобильному интернету.

### 2. Выключить операторов
`Настройки → Network & servers → Operators`: выключить **всех** (SimpleX Chat, Flux и
любых других).

Это самый важный шаг и самый легко забываемый. Оставленный включённым оператор означает,
что часть трафика пойдёт через публичные релеи — то есть контур не выполняет свою задачу.
На Android этот экран просто скрыт (`patches/0002`), на стоковом iOS его надо выключить
руками.

### 3. SMP-сервер
Удалить все предустановленные, добавить один — `smp://<fp>:<pass>@<node.host>:5223`.
Отметить «Use for new connections».

### 4. XFTP-сервер
Аналогично: `xftp://<fp>:<pass>@<node.host>:5443`.

### 5. ICE-серверы (звонки)
`Settings → Audio & video calls → WebRTC ICE servers`: заменить содержимое целиком на
строки из чек-листа, **по одной в строке, ровно как выданы**:

```
stun:<node.host>:3478
turn:<timestamp>:<credential>@<node.host>:3478
```

Публичные STUN/TURN (`stun.simplex.im`, `stun.l.google.com`) удалить.

Два предупреждения, оба неочевидные:

- **Формат менять нельзя.** Клиент разбирает строку через `java.net.URI`. Если хоть
  одна строка введена с ошибкой, `parseRTCIceServers` возвращает `null` для **всего
  списка**, и приложение молча возвращается на публичные серверы SimpleX. Звонки при
  этом работают — просто через третью сторону. Проверьте список после ввода.
- **Креды живут ограниченное время** (`turn.credential_ttl_secs`, по умолчанию 30 суток
  = период ротации секрета). После ротации перевыпустите чек-лист: сообщения будут
  ходить, а звонки перестанут — симптом неочевидный.

### 6. Приватность и уведомления
- Private message routing: **Always**;
- Notifications: **No push server** (Off). На iOS и Instant, и Periodic работают через
  push-сервер SimpleX — третью сторону, которой в контуре нет. Цена: о новом сообщении
  узнаёте, только открыв приложение. Свой push-сервер — только у приложения Hearth
  ([ADR 0016](adr/0016-own-push-server.md));
- Исчезающие сообщения — включить для новых контактов (7 дней), как на Android;
- Экранная блокировка приложения (Face ID / пароль) — включить;
- iCloud Backup для приложения — **выключить** (аналог `allowBackup=false`, ТЗ §3.1).

## Проверка

- В списке серверов ровно один SMP и один XFTP, оба на `<node.host>`.
- Операторы выключены все.
- Отправка и получение сообщения работают.
- Звонок между двумя устройствами в разных сетях проходит и слышен (A8).

## Чего стоит ожидать

| | Android (форк) | iOS (сток) |
|---|---|---|
| Настройка | один QR, ≤ 5 минут | 6 шагов вручную |
| Пресеты операторов | экрана нет | можно случайно включить обратно |
| FLAG_SECURE | всегда | нет аналога |
| Бэкапы ОС | запрещены манифестом | выключать вручную в iCloud |
| Обновления | внутренний F-Droid | App Store, стоковая сборка |

Отсюда рекомендация: пока iOS-форка нет (фаза 2, ТЗ §13), стоковые iOS-устройства
считать **менее защищёнными** и держать это в голове при добавлении людей в контур.

## Desktop

То же самое, стоковый клиент. Отдельно проверить, что у приложения нет
