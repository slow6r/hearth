# Архитектура

Документ отвечает на один вопрос: **почему это устроено именно так**. Что именно
устроено — в [ТЗ](tz.md); как этим пользоваться — в runbook'ах.

---

## 1. Что защищает что

Разные вещи защищены разными механизмами, и путать их не стоит.

| Что | Чем защищено | От кого |
|---|---|---|
| Содержимое сообщений | E2E-шифрование SimpleX | все, включая владельца релея |
| Подлинность сервера | отпечаток CA в адресе `smp://<fp>:...` | MITM |
| Создание очередей | `create_password` в `[AUTH]` | посторонние из интернета |
| Управление узлом | LAN + mTLS + отпечаток сертификата | все остальные |
| Факт и объём общения | **ничем** | наблюдатель на канале |

Последняя строка — прямое следствие [ADR 0007](adr/0007-public-relay-no-vpn.md): релей
публичен, и это цена, которую мы платим за отсутствие VPN и за работающие звонки между
устройствами за NAT.

## 1.1. Идея, которую добавляет этот проект: узел ничего не инициирует

Релеи — стоковые Haskell-бинари, никто их построчно не читает, и это нормально:
пересобрать доверие к чужому коду ревью нельзя. Вместо доверия строится
**наблюдаемость** одного конкретного свойства: клиенты подключаются *внутрь*, а сам
узел не должен открывать ни одного исходящего соединения.

Попытка это сделать:

1. **не проходит** — `output` policy drop в nftables; разрешены только LAN и одно
   явное исключение (ниже);
2. **попадает в счётчик** — именованный `egress_drop`, который `hearthd` читает раз в
   30 секунд;
3. **попадает в журнал** — `hearth-egress-drop` с адресом назначения;
4. **становится инцидентом навсегда** — critical-алерт + запись в
   `egress-incidents.jsonl`, который не ротируется.

Ожидаемое значение `egress_drop` за сутки — ноль. Не «мало», а ноль.

**Единственное исключение — медиатрафик coturn.** Релеемый звонок означает, что coturn
отправляет пакеты второму участнику, который находится где-то в интернете. Это
настоящее исходящее соединение, не ответ на входящее, и разрешить его пришлось явно.
Ограничено настолько узко, насколько позволяет механизм: только пользователь
`turnserver`, только UDP, только из диапазона аллокаций. Всё остальное на узле —
включая сами релеи — по-прежнему не может открыть исходящее соединение, не попав
в `egress_drop`.

Второй независимый сигнал — скан сокетов (`ss -tnp`). Счётчик ловит **заблокированное**;
скан ловит **пропущенное** — ситуацию, когда правила не загрузились или их обошли.

**Отдельный важный случай:** watchdog, который не может прочитать счётчики, внешне
выглядит точно как чистый узел. Поэтому «не могу прочитать nft» — это тоже алерт
(`counters_readable: false`), а не тишина.

## 2. Что написано на Rust и почему так мало

ТЗ §0 задаёт правило: на Rust пишем только то, чего в SimpleX нет и не было. Ни одна
строка upstream не переписывается. Поэтому `hearthd` — это **обвязка узла**, а не
мессенджер:

| Модуль | Зачем существует |
|---|---|
| `supervisor` | systemd не знает, что «active» процесс может не принимать соединения |
| `egress` | детектор исходящих соединений узла |
| `integrity` | доказать, что запущено ровно то, что проверяли (A12) |
| `backup` | шифрованный архив, который сам узел прочитать не может |
| `configgen` | превратить состояние узла в QR: адреса релеев + ICE для звонков |
| `migrate` | переезд железа без смены адреса релея (§10.2) |
| `api` + `hearthctl` | всё вышеперечисленное — руками владельца, только из LAN |

Ни один из этих модулей не читает содержимое сообщений и не логирует адреса клиентов
(ТЗ §7.4). Релей для `hearthd` — чёрный ящик с портом и юнитом.

## 3. Адрес релея переживает железо

Ключевое свойство контура (ТЗ §2.5): клиентский адрес

```
smp://<отпечаток CA>:<пароль>@relay.example.org:5223
```

состоит из трёх вещей, ни одна из которых не привязана к конкретной машине:

- **отпечаток CA** — файл в `/etc/opt/simplex`, создан один раз при `smp-server init`;
- **пароль на создание очередей** — файл в `/etc/hearth/secrets`;
- **публичное имя** (`node.host`) — DNS-запись, которую обновляет роутер, а не узел.

Отсюда вся процедура §10.2 сводится к «перенести каталоги и переставить проброс», а
не к «перенастроить всех». `hearthctl migrate export` останавливает релеи (чтобы store
log не менялся во время копирования), делает один age-шифрованный архив и печатает
sha256; `migrate import` на новой машине проверяет хеш, раскладывает файлы и сверяет
бинари с манифестом.

Экспорт **намеренно оставляет релеи остановленными**: два узла с одним CA и одним
адресом — это split brain, который клиент обнаружить не может.

## 4. Границы доверия

```
┌─ Интернет ───────────────────────────────────────────────────────────────┐
│  Клиенты семьи (любая сеть, VPN не нужен)                                │
│         │ входящие: 5223, 443, 5443/tcp · 3478 udp+tcp · 49160-49200/udp │
│         ▼                                                                │
│  исходящих у узла нет, кроме медиапотока coturn ──────────────────┐      │
└───────────────────────────────────────────────────────────────────┼──────┘
                          │ проброс портов на роутере               │
┌─ Домашняя сеть 192.168.1.0/24 ──────────────────────────────────── ┼──────┐
│                                                                    │      │
│  192.168.1.10  hearth-node: smp + xftp + coturn + hearthd ─────────┘      │
│                admin API :7443 — только отсюда, mTLS                      │
│  192.168.1.20  hearth-backup: только принимает rsync по ssh               │
│  192.168.1.1   роутер: проброс портов, DDNS, NTP, Gotify                  │
└───────────────────────────────────────────────────────────────────────────┘
```

Обратите внимание на асимметрию: мессенджер публичен, управление — нет. Порты 7443 и 22
не пробрасываются, `api.listen` на wildcard отвергается конфигом, а `Config::validate`
требует, чтобы `admin_networks` лежали внутри `lan_networks`.

Три уровня контроля доступа к admin API, каждый независим от остальных:

1. **адрес источника** — только `admin_networks`;
2. **mTLS** — сертификат должен быть выписан admin CA `hearthd`;
3. **отпечаток** — sha256 сертификата должен быть в `admins.json` и не отозван.

Третий уровень перечитывается на **каждом соединении**, поэтому отзыв админа действует
сразу, без перезапуска демона. Это проверяется e2e-тестом
`a_revoked_admin_certificate_is_refused`.

Почему авторизация по отпечатку, а не по CN — [ADR 0004](adr/0004-fingerprint-auth.md).

## 5. Ключи и кто чем владеет

| Ключ | Где живёт | Кто может использовать |
|---|---|---|
| CA релея (`/etc/opt/simplex`) | на узле, внутри LUKS | релей; входит в адрес |
| Пароль на создание очередей | `/etc/hearth/secrets`, 0600 | `hearthd` — для сборки bundle |
| Статический секрет TURN | `/etc/hearth/secrets`, ротация раз в месяц | coturn + `hearthd` |
| admin CA (`/etc/hearth/pki`) | на узле | выписывает клиентские сертификаты |
| Клиентский сертификат админа | рабочая станция владельца | `hearthctl` |
| **age-ключ бэкапов (приватный)** | **вне узла**: YubiKey / офлайн-копия | только владелец |
| Ключ подписи APK | офлайн, hardware-backed | ручная подпись релиза |

Асимметрия бэкапа сделана намеренно: `hearthd` умеет **создать** архив, но не умеет его
**прочитать**. Компрометация узла не даёт доступа к истории бэкапов. Обратная сторона —
потеря age-ключа означает потерю всех бэкапов, поэтому ТЗ §14 требует второй экземпляр
ключа у другого взрослого.

## 6. Почему нет второго релея

Резерв означал бы либо вторую машину дома (тогда клиентам нужно прописать оба адреса
**с первого дня** — upstream не переносит контакты между релеями), либо сервер вне дома,
что прямо запрещено ТЗ §1.2.

Принятая цена: узел выключен → сообщения копятся на клиентах и доставляются при
возврате. Store log включён именно для этого, а acceptance-тест A7 проверяет, что так
и происходит.

## 7. Где реализация отклоняется от буквы ТЗ

Все отклонения — в [ADR](adr/), каждое с обоснованием. Коротко:

| Отклонение | Почему |
|---|---|
| **Публичный релей вместо доступа только через WG** ([0007](adr/0007-public-relay-no-vpn.md)) | так разворачивают SimpleX; без этого не работают звонки между двумя NAT |
| `systemctl` вместо `zbus` | −30 зависимостей, не нужен доступ к D-Bus сокету |
| Именованные счётчики nft вместо анонимных | анонимные нельзя прочитать по имени |
| `POST /migrate/export` (а не `GET`) | GET не должен останавливать мессенджер |
| `/var/lib/hearth` — четвёртый каталог в бэкапе | история инцидентов обязана переживать переезд |
| Авторизация по отпечатку сертификата | не нужен X.509-парсер, отзыв работает мгновенно |
| ICE в bundle — строки, а не объекты | ТЗ Приложение B описывает `{urls, username, credential}`, но клиент парсит строку `turn:user:cred@host:port` |
| Нет проверки «релей не слушает 0.0.0.0» | upstream: `host` в ini не биндит вовсе |

## 8. Звонки: почему это отдельная история

Сообщения идут через релей — простую трубу. Звонок так не умеет: это WebRTC, то есть
прямое соединение между устройствами, и оно собирается через ICE.

Когда оба участника за NAT (два телефона в мобильных сетях — обычный случай), прямое
соединение не устанавливается, и медиапоток идёт **через TURN**. Отсюда три следствия,
каждое из которых стоило отдельного решения:

1. **TURN обязан быть публичным.** Он точка встречи для двух устройств, ни одно из
   которых не находится в домашней сети.
2. **TURN обязан иметь право слать наружу.** Это единственное исключение в output-цепочке
   (§1.1), ограниченное по `skuid` и диапазону портов.
3. **TURN нельзя оставить открытым.** Публичный форвардер пакетов без ограничений — это
   и доступ в домашнюю сеть, и чужой бесплатный релей. Закрыто через `denied-peer-ip`
   на все приватные диапазоны + `use-auth-secret` + квоты.

Отдельная тонкость, которая стоила подбора credential'а в `configgen/turn.rs`: клиент
хранит ICE-серверы **строкой** `turn:user:cred@host:port` и разбирает её через
`java.net.URI`. Если в credential попадёт `/`, запись отвалится — а `parseRTCIceServers`
при одной плохой записи возвращает `null` для **всего списка**, и клиент откатывается на
**публичные** STUN/TURN SimpleX. То есть ошибка в одном символе привела бы не к
сломанным звонкам, а к тихой утечке на третью сторону. Поэтому hearthd подбирает
timestamp, у которого HMAC не содержит `/`, и валидация формата продублирована на
устройстве.
