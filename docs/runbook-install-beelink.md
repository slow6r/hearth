# Runbook: установка на Beelink Mini S12 Pro (Debian 13)

Машина многоцелевая: стоит в спортзале, подключена к телевизору, на ней проходят
занятия по Zoom и VK Звонкам — и она же держит релей мессенджера.

Разбор компромисса, на который это идёт, — [ADR 0008](adr/0008-multi-purpose-host.md).
Общая процедура развёртывания релея — [runbook-deploy.md](runbook-deploy.md); здесь
только то, что специфично для этой машины.

**Время:** 2–3 часа.

---

## 0. Что понадобится

- [ ] USB-флешка ≥ 2 ГБ под установщик
- [ ] клавиатура (для BIOS и ввода пароля LUKS при загрузке)
- [ ] кабель Ethernet — установщик netinst качает пакеты из сети
- [ ] образ `debian-13.x-amd64-netinst.iso`
- [ ] UPS (можно позже, но лучше сразу — см. §7)
- [ ] публичное имя `node.host`: домен с динамическим DNS

---

## 1. BIOS

Включение → `Del`. Загрузочное меню → `F7`.

| Параметр | Значение | Зачем |
|---|---|---|
| **Restore on AC power loss** | **Power On** | После отключения света машина поднимется сама. Без этого мессенджер лежит до прихода человека |
| Wi-Fi | Disabled | У сервера не должно быть радиоинтерфейсов |
| Bluetooth | Disabled | То же |
| Secure Boot | Disabled | Debian с LUKS ставится проще. Включать имеет смысл **только вместе с FDE**, и прежде всего в варианте «LUKS + разблокировка по TPM»: без Secure Boot значения PCR ничего содержательного не измеряют. На узле без шифрования Secure Boot не даёт ничего — тот, кто добрался до диска, правит `initramfs` напрямую ([ADR 0009](adr/0009-no-full-disk-encryption.md)) |
| Intel PTT (fTPM) | Enabled | Пригодится, если позже переведёте разблокировку на TPM |

Первый пункт проверьте не на слово: после установки выдерните питание из розетки,
воткните обратно и убедитесь, что машина включилась сама.

## 2. Установка Debian 13

Debian 13 (trixie), а не 12: у него новее glibc, а значит подойдёт **любой** из
релизных бинарей SimpleX — и собранный под Ubuntu 22.04, и под 24.04. На Debian 12
годился бы только первый.

Флешка: `dd if=debian-13.x-amd64-netinst.iso of=/dev/sdX bs=4M status=progress`
(или Rufus/BalenaEtcher на Windows).

Шаги установщика:

| Шаг | Что выбрать |
|---|---|
| Разметка дисков | **Guided — use entire disk and set up encrypted LVM** |
| Пароль шифрования | Длинный. Записать. Восстановлению не подлежит |
| Пароль root | **Задать** — тогда первый пользователь не получит sudo автоматически |
| Первый пользователь | **Админский, ваш.** Пользователя зала заведём отдельно |
| Popularity contest | **Нет** — он отправляет статистику наружу |
| Выбор ПО | `Debian desktop environment` + `GNOME`, `SSH server`, `standard system utilities`. Веб-сервер и печать — снять |

## 3. Два пользователя

Это то, что реально защищает ключи релея на машине, которая работает круглосуточно и
к которой подходят люди.

```bash
# пользователь зала — БЕЗ sudo
sudo adduser gym
# проверить, что он не в sudo:
groups gym
```

Ключи релея лежат в `/etc/opt/simplex` и `/etc/hearth/secrets` с правами `0600` и
владельцем root/simplex. Человек, подошедший к включённому компьютеру под учёткой
`gym`, прочитать их не может — нужен root, а его у него нет.

Вы заходите по SSH под своей учётной записью.

**Автологин зала:** Настройки → Пользователи → `gym` → Автоматический вход.

> **Условие, без которого этот шаг делать нельзя.** Автовход допустим **только** для
> учётки, которой нет ни в группе `sudo`, ни в `sudoers`. Проверьте перед включением, а
> не после:
>
> ```bash
> groups gym | tr ' ' '\n' | grep -x sudo    # ожидается: пусто
> sudo -n -l -U gym                          # ожидается: отказ, не список правил
> ```
>
> На `fels` это условие не проверили, и автовход приземлился на учётку с
> `NOPASSWD: ALL` — то есть машина круглосуточно стоит в зале с открытой
> root-эквивалентной сессией ([ADR 0008](adr/0008-multi-purpose-host.md), дополнение
> 2026-09-18). Разбор и обратный порядок:
> [runbook-host-hardening.md](runbook-host-hardening.md).

## 4. Экран гаснет, машина работает

```bash
# Никакого сна — никогда
sudo systemctl mask sleep.target suspend.target hibernate.target hybrid-sleep.target
```

От имени `gym` (или через Настройки → Питание):

```bash
gsettings set org.gnome.desktop.session idle-delay 600
gsettings set org.gnome.settings-daemon.plugins.power sleep-inactive-ac-type 'nothing'
gsettings set org.gnome.settings-daemon.plugins.power power-button-action 'nothing'
# блокировку экрана можно не включать — но ТОЛЬКО потому, что gym без прав.
# Если автовход стоит на учётке с sudo, эта строка означает «root-шелл у телевизора
# круглосуточно»: сначала уберите sudo (runbook-host-hardening.md §1.2), потом решайте
# про локскрин. Проверка условия — в §3 выше.
gsettings set org.gnome.desktop.screensaver lock-enabled false
```

Через 10 минут простоя DPMS отправит телевизор в standby, машина продолжит работать.

Проверка: подождать 10 минут, убедиться, что телевизор погас, и из другой комнаты
зайти по SSH — сервер должен отвечать.

## 5. Приложения зала — через Flatpak

Flatpak даёт песочницу: приложение не видит файловую систему хоста. На машине, где
рядом лежит приватный ключ CA релея, это существенно лучше, чем `.deb`.

```bash
sudo apt install flatpak gnome-software-plugin-flatpak
sudo flatpak remote-add --if-not-exists flathub https://flathub.org/repo/flathub.flatpakrepo
# от имени gym:
flatpak install flathub com.VK.Messenger us.zoom.Zoom
```

Урезать права:

```bash
flatpak override --user --nofilesystem=host com.VK.Messenger
flatpak override --user --nofilesystem=host us.zoom.Zoom
# посмотреть, что получилось:
flatpak info --show-permissions com.VK.Messenger
```

Если отвалится отправка файлов — вернуть точечно: `--filesystem=xdg-download`.

> Пакет VK на Flathub помечен «не проверено» и собран сообществом, не самим VK.
> Песочница как раз и нужна затем, чтобы это было не страшно.

**Демонстрация экрана в Zoom** на Wayland капризна. Для занятий обычно не нужна;
если понадобится — на экране входа выберите сессию «GNOME on Xorg».

## 6. Разблокировка диска после сбоя питания

Зашифрованный корень спрашивает пароль при каждой загрузке. Клавиатура в зале есть,
но идти туда в три ночи не хочется.

```bash
sudo apt install dropbear-initramfs
# положить свой публичный SSH-ключ:
sudo tee -a /etc/dropbear/initramfs/authorized_keys < ~/.ssh/id_ed25519.pub
# статический адрес для initramfs (иначе он не поднимет сеть):
echo 'IP=192.168.1.10::192.168.1.1:255.255.255.0::enp1s0:off' | \
    sudo tee -a /etc/initramfs-tools/initramfs.conf
sudo update-initramfs -u
```

После этого при загрузке машина поднимает сеть и ждёт. Подключаетесь с телефона:

```bash
ssh -p 22 root@192.168.1.10      # порт dropbear, по умолчанию тот же
cryptroot-unlock                  # вводите пароль LUKS
```

Загрузка продолжается. В зал идти не надо.

> Что LUKS здесь даёт и чего не даёт — [architecture.md §5](architecture.md).
> Коротко: он защищает диск **в покое**. Машина работает круглосуточно, так что
> реальные сценарии — «диск уехал отдельно» и «коробку забрали выключенной».

## 7. UPS

Не «желательно», а нужно, и причина конкретная: при `store_messages = memory`
недоставленные сообщения сохраняются на диск только при **штатной** остановке.
Отключение питания их теряет.

```bash
sudo apt install nut
# настроить nut на корректный shutdown, см. /usr/share/doc/nut/
```

Получаса автономии достаточно: задача UPS здесь не «пережить отключение», а
«успеть корректно выключиться».

## 8. Дальше — общий runbook

Сеть, проброс портов, nftables, релеи, hearthd, мониторинг:
[runbook-deploy.md](runbook-deploy.md).

Два места, где для этой машины надо отступить от общего текста:

1. **`hearth.nft`** — в правило `app_egress` добавьте пользователя `gym`, иначе
   VK и Zoom не выйдут в интернет, а их трафик поднимет ложный инцидент.
2. **Резолвер оставьте включённым.** Общий runbook его выключает — это верно для
   однозадачного узла, но браузеру и Zoom нужен DNS. Это осознанное отступление,
   зафиксированное в ADR 0008.

## Порядок проверки, когда всё встало

```bash
hearthctl health                          # все сервисы ok; строка backup= на новом
                                          # узле честно скажет Down, пока не отработал
                                          # первый бэкап (hearthctl backup now)
hearthctl egress                          # egress_drop = 0, app_egress растёт — так и надо
sudo tests/acceptance/run-all.sh          # A1, A2, A3, A12
TARGET=<node.host> ./a04-port-scan.sh     # с телефона по мобильной сети: 7443 и 22 закрыты
```

Плюс два ручных теста, которые ничем не заменить:

- **A8:** звонок между двумя устройствами в разных сетях — идёт и слышен;
- **питание:** выдернуть шнур, вставить обратно — машина поднялась сама и ждёт
  разблокировки по SSH.
